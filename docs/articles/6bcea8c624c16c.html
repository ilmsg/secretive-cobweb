🐥 การออกแบบ Marketplace คล้าย Etsy

การออกแบบ Marketplace คล้าย Etsy (ซึ่งเป็นแพลตฟอร์มซื้อขายงานฝีมือ สินค้าแฮนด์เมด และสินค้าวินเทจแบบ Multi-vendor) ด้วยภาษา Rust เป็นการตัดสินใจที่ยอดเยี่ยมในแง่ของประสิทธิภาพ (Performance), ความปลอดภัยของหน่วยความจำ (Memory Safety), และการรองรับการทำ Concurrency สูง
สถาปัตยกรรมและโครงสร้างการออกแบบระบบ (System Design) สามารถแบ่งออกเป็นส่วนสำคัญได้ดังนี้:

  1. การเลือก Tech Stack (Rust Ecosystem)

เพื่อให้พัฒนาได้รวดเร็วและเสถียร ควรเลือกใช้ Crate ที่เป็นที่นิยมและมี Community แข็งแรง:
• Web Framework: Axum (แนะนำที่สุดในปัจจุบัน เพราะทำงานร่วมกับ Tokio และ Towerได้ดีมาก มีความยืดหยุ่นและเรียนรู้ไม่ยาก) หรือ Actix-web (ประสิทธิภาพสูงสุด)
• Async Runtime: Tokio (มาตรฐานหลักของ Rust)
• Database & ORM:
• PostgreSQL (เหมาะกับข้อมูลที่มีความสัมพันธ์ซับซ้อน เช่น Order, User, Shop)
• SQLx (เขียน Raw SQL ที่ตรวจสอบความถูกต้องตอน Compile-time ได้) หรือ SeaORM (หากชอบแบบ ActiveRecord / ORM เต็มรูปแบบ)
• Search Engine: Meilisearch (เขียนด้วย Rust เร็วมาก และทำ Faceted Search/Filter ได้ง่ายคล้าย Etsy) หรือ Elasticsearch
• Caching & Session: Redis (ใช้ deadpool-redis หรือ fred) สำหรับเก็บตะกร้าสินค้า (Cart) และ Rate Limiting
• Storage (รูปภาพสินค้า): AWS S3 หรือ Cloudflare R2 (ใช้ aws-sdk-s3 ร่วมกับ Crate image เพื่อย่อขนาดและแปลงไฟล์เป็น WebP อัตโนมัติ)
• Payment Gateway: Stripe Connect (สำคัญมากสำหรับ Marketplace เพราะต้องรองรับการแบ่งเงินให้ผู้ขายหลายราย - Split Payments) ใช้ Crate async-stripe

  1. สถาปัตยกรรมระบบ (System Architecture)

สำหรับระยะเริ่มต้น (MVP) แนะนำให้เริ่มจาก Modular Monolith (แบ่งโค้ดเป็น Module ชัดเจนในโปรเจกต์เดียว) เพื่อลดความซับซ้อนในการ Deploy และค่อยแยกเป็น Microservices เมื่อระบบใหญ่ขึ้น
โครงสร้าง Folder (Workspace) ที่แนะนำ:

etsy-clone/
├── Cargo.toml          # Workspace configuration
├── migrations/         # ไฟล์ SQL migration (sqlx-cli)
├── crates/
│   ├── api/            # Axum routes, middlewares, handlers
│   ├── core/           # Business logic, Domain models, Traits
│   ├── db/             # Database connection, SQL queries
│   ├── search/         # ตัวเชื่อมต่อ Meilisearch
│   └── worker/         # Background jobs (ส่งอีเมล, ประมวลผลรูปภาพ)
  1. การออกแบบฐานข้อมูลหลัก (Core Database Schema)

หัวใจของ Marketplace แบบ Etsy คือการที่ 1 User สามารถเปิดร้านค้า (Shop) ได้ และ 1 คำสั่งซื้อ (Order) อาจมีสินค้าจากหลายร้านค้าปนกัน
• users: id, email, password_hash, role (Buyer, Seller, Admin), created_at
• shops: id, owner_id (FK -> users), shop_name, slug, description, stripe_account_id, rating
• categories: id, parent_id (รองรับหมวดหมู่ย่อย), name, slug
• products: id, shop_id (FK -> shops), category_id, title, description, base_price, is_handmade, is_vintage, status
• product_variants: id, product_id, sku, attributes (JSONB เช่น {"color": "red", "size": "M"}), price_override, stock_quantity
• orders (Master Order): id, buyer_id, total_amount, payment_intent_id, status
• sub_orders (Shop Order): id, order_id (FK -> orders), shop_id (FK -> shops), subtotal, shipping_status, tracking_number (แยกตามร้านค้าเพื่อให้ผู้ขายแต่ละคนจัดการจัดส่งของตัวเองได้)
• order_items: id, sub_order_id, variant_id, quantity, unit_price, customization_note (สำคัญสำหรับ Etsy ที่ลูกค้ามักสั่งสลักชื่อหรือปรับแต่งสินค้า)
• reviews: id, order_item_id, buyer_id, shop_id, rating, comment, images

  1. ฟีเจอร์สำคัญและความท้าทายทางเทคนิค (Key Challenges & Solutions)

  2. การจัดการสต็อกสินค้าพร้อมกัน (Concurrency & Inventory):
    • ปัญหา: งานแฮนด์เมดมักมีชิ้นเดียว ถ้าคนกดซื้อพร้อมกันอาจเกิดการขายเกิน (Overselling)
    • ทางแก้ใน Rust: ใช้ Database Transaction (sqlx::Transaction) ร่วมกับ SELECT ... FOR UPDATE เพื่อ Lock แถวข้อมูลสต็อกชั่วคราวขณะตัดยอด

  3. ระบบชำระเงินแบบ Multi-Vendor (Split Payments):
    • ทางแก้: ใช้ Stripe Connect เมื่อผู้ซื้อจ่ายเงินก้อนเดียว ระบบจะหักค่าธรรมเนียมแพลตฟอร์ม (Platform Fee เช่น 6.5% เหมือน Etsy) และโอนส่วนที่เหลือเข้าบัญชีผู้ขายแต่ละร้านโดยอัตโนมัติ

  4. ระบบค้นหาและตัวกรอง (Search & Discovery):
    • ทางแก้: เมื่อมีการสร้างหรือแก้ไขสินค้าใน PostgreSQL ให้ส่ง Event ผ่าน Channel (เช่น tokio::sync::mpsc หรือ Redis Streams) เพื่อให้ Background Worker อัปเดตข้อมูลไปยัง Meilisearch แบบ Real-time ทำให้ค้นหาตามสี ราคา วัสดุ และสถานที่จัดส่งได้ในระดับมิลลิวินาที

  5. ระบบข้อความระหว่างผู้ซื้อและผู้ขาย (Real-time Chat):
    • ทางแก้: ใช้ WebSockets ใน Axum (axum::extract::ws) ร่วมกับ Redis Pub/Sub เพื่อรองรับการส่งรูปภาพตัวอย่างงานสั่งทำ (Custom Orders)

  6. ตัวอย่างโครงสร้างโค้ด (Axum + SQLx)

ตัวอย่างการสร้าง Endpoint สำหรับสร้างสินค้าใหม่พร้อมเช็กสิทธิ์เจ้าของร้าน:

use axum::{extract::{State, Json}, http::StatusCode, response::IntoResponse};
use serde::{Deserialize, Serialize};
use sqlx::PgPool;
use uuid::Uuid;

#[derive(Deserialize)]
pub struct CreateProductReq {
    pub shop_id: Uuid,
    pub title: String,
    pub description: String,
    pub price_cents: i64, // เก็บเงินเป็นหน่วยย่อยสุด (สตางค์/เซ็นต์) เลี่ยงปัญหา Floating point
    pub stock: i32,
}

#[derive(Serialize)]
pub struct ProductRes {
    pub id: Uuid,
    pub title: String,
}

pub async fn create_product(
    State(pool): State<PgPool>,
    // AuthUser คือ Custom Extractor ที่ตรวจสอบ JWT Token
    auth_user: AuthUser, 
    Json(payload): Json<CreateProductReq>,
) -> Result<impl IntoResponse, (StatusCode, String)> {
    
    // 1. ตรวจสอบว่า User เป็นเจ้าของร้านนี้จริงหรือไม่
    let is_owner = sqlx::query_scalar!(
        "SELECT EXISTS(SELECT 1 FROM shops WHERE id = $1 AND owner_id = $2)",
        payload.shop_id,
        auth_user.user_id
    )
    .fetch_one(&pool)
    .await
    .map_err(|e| (StatusCode::INTERNAL_SERVER_ERROR, e.to_string()))?;

    if !is_owner.unwrap_or(false) {
        return Err((StatusCode::FORBIDDEN, "คุณไม่มีสิทธิ์จัดการร้านค้านี้".into()));
    }

    // 2. บันทึกสินค้าลงฐานข้อมูล
    let product_id = Uuid::new_v4();
    sqlx::query!(
        r#"
        INSERT INTO products (id, shop_id, title, description, base_price)
        VALUES ($1, $2, $3, $4, $5)
        "#,
        product_id,
        payload.shop_id,
        payload.title,
        payload.description,
        payload.price_cents
    )
    .execute(&pool)
    .await
    .map_err(|e| (StatusCode::INTERNAL_SERVER_ERROR, e.to_string()))?;

    Ok((StatusCode::CREATED, Json(ProductRes { id: product_id, title: payload.title })))
}

ข้อแนะนำเพิ่มเติมสำหรับ Frontend

เนื่องจาก Rust เหมาะกับการทำ Backend API ส่วนหน้าบ้าน (Frontend) แนะนำให้ใช้ Next.js (React) หรือ SvelteKit เพื่อทำ SSR (Server-Side Rendering) ซึ่งสำคัญมากสำหรับ Marketplace เพราะหน้าสินค้าทุกรายการต้องติดอันดับ SEO บน Google ได้ดีครับ

หากต้องการเจาะลึกส่วนใดเป็นพิเศษ สามารถแจ้งได้เลยครับ เช่น:
• โครงสร้าง Database Schema แบบละเอียด (SQL Migration)
• การออกแบบระบบ ตะกร้าสินค้าและ Checkout แบบ Multi-vendor
• ตัวอย่างการวาง Project Boilerplate ด้วย Axum และ SQLx
• การเชื่อมต่อ Frontend (เช่น Next.js) เข้ากับ Rust Backend
